# pycards — план реализации

Тренажёр-карточки «what does this print?» по учебнику
«🐍 Python для автоматизации тестирования» (Notion, 120 тем, 7 блоков).
Мобильный PWA, UI на английском, карточки и прогресс — локально.

Статус: все решения приняты (раздел 2, 3). Репозиторий: github.com/IlyaBesedin/pycards (private, пустой).

---

## 1. Анализ исходника

База Notion `collection://cebd3f54-c1de-4781-9009-f9f8158492d9`:
120 тем (№ 1–120) + 9 страниц «🔁 Повторение» (№ x.5, без блока).
Свойства: `Блок` (7 значений), `Неделя` (1–9), `Сложность`
(базовый/средний/продвинутый), `Status`, `№`.

Структура каждой страницы: `🎯 Что изучить` → `📚 Конспект` (с кодом) →
`⚠️ Частые ошибки` → `🔗 Документация` → `✅ Самопроверка` → `🤖 Промпт`.

Готовых карточек нет — генерируем из сниппетов «Конспекта», ловушек
«Частых ошибок» и вопросов «Самопроверки» про вывод.

| Блок | Тем | Применимость формата «что напечатает?» |
|---|---|---|
| 1. База Python | 38 (1–38) | полная |
| 2. Алгоритмы | 14 (39–52) | хорошая: «что вернёт», «сколько итераций», `O(n log n)` |
| 3. Основы автоматизации | 16 (53–68) | половина: генераторы/декораторы/mock — да; CI, фермы — тип `truth` |
| 4. UI / API / БД | 16 (69–84) | смешанная: HTTP-код, SQL → число, селектор → «сколько найдёт» |
| 5. PyTest | 14 (85–98) | хорошая: «сколько соберёт», `2 passed, 1 xfailed` |
| 6. Requests | 10 (99–108) | средняя: status_code, имя исключения; проверка вручную |
| 7. Playwright | 12 (109–120) | сложная: «пройдёт ли expect», «бросит ли TimeoutError» |

Темп учебника: ~14 тем/неделю = 2 темы/день ≈ 20 карточек/день —
совпадает с дефолтным лимитом Anki.

## 3. Счёт — принят вариант B «долг карточки»

Проблема с чистым «+1 / −1 за каждый ответ»: неверная карточка возвращается
в сессии (правило ≥10), и один и тот же вопрос отвечают несколько раз.
«Неверно, неверно, неверно, верно» = −3 + 1 = −2 — хотя карточка в итоге
выучена. Трудная сессия, в которой всё закрыто, заканчивается в глубоком
минусе, и система «утешает» человека, который на самом деле справился.

Варианты:

**A. Чистый ±1** (как в ТЗ). Просто и прозрачно. Минус: дрейф в минус на
трудном материале; при повторениях через дни счёт растёт бесконечно
(измеряет «сколько отвечал», а не «сколько знаю»).

**B. Долг карточки — ПРИНЯТО.** Сессионный счёт:
- верно с первого раза: **+1**
- неверно (первый раз в сессии): **−1**
- неверно повторно на той же карточке: **0** (долг уже записан)
- верно на возвращённой карточке: **+1** (долг погашен)

Итог: карточка даёт +1 (знал), 0 (выучил в сессии), −1 (ещё не закрыта).
Минус = «сколько карточек сейчас в долгу». Завершённая сессия всегда ≥ 0
и равна числу карточек, взятых с первого раза. Сообщения реагируют на
каждое изменение, включая −1 на ошибке и «recovered» при выходе из минуса.

**C. ±1 на первую попытку, повторы не считаются.** Счёт = знал − не знал,
без погашения. Может закончиться в минусе, но без дрейфа от повторов.

Сквозной счёт = сумма сессионных. Отдельно в статистике — Anki-метрики:
new / learning / young (< 21д) / mature (≥ 21д), first-try accuracy.


### Схема карточки

```json
{
  "id": "b1-002-03",
  "topic": 2,
  "block": 1,
  "difficulty": "базовый",
  "kind": "output",
  "question": "What does this print?",
  "code": "words = [\"a\", \"bb\", \"ccc\"]\nfor w in words:\n    w = w.upper()\nprint(words)",
  "answer": "['a', 'bb', 'ccc']",
  "accepted": ["[\"a\", \"bb\", \"ccc\"]"],
  "explanation": "`w` is rebound to a new uppercase string; the list is untouched. Strings are immutable.",
  "tags": ["mutability", "for"],
  "verify": "exec"
}
```

`kind`: `output` · `exception` · `value` · `pytest` · `truth`.
`verify`: `exec` (subprocess, timeout 2 с, без сети) · `pytest` · `manual`.
Ограничения авторинга (проверяет `verify_cards.py`): ≤ 12 строк, ≤ 44 символа
в строке — чтобы код читался на телефоне без переноса.

## 5. Алгоритм показа (референс — Anki)

### Состояния карточки
- `new` — ни разу не отвечали
- `learning` — в процессе (ответили неверно, ещё не закрыли)
- `review` — выучена, есть интервал и дата `due`
- `lapsed` — была review, ответили неверно → relearn в сессии, затем снова review

### Интервалы (SM-2 lite, бинарная оценка)
- первый верный: interval = 1д, ease = 2.5
- далее: interval × ease с округлением и ±5% фаззом: 1 → 3 → 8 → 20 → 50 → 125д; cap 180д
- неверно на review: lapses++, ease = max(1.3, ease − 0.2), interval → 1д после закрытия
- неверно на new/learning: ease не меняется (как в Anki)
- due = lastReview + interval; в сессию попадают due ≤ сегодня

### Лимит новых карточек
Каждая новая карточка порождает цепочку будущих повторов (1, 3, 8, 20… дней).
100 новых сегодня = ~100 повторов завтра и лавина через неделю. Anki держит
20 новых/день, чтобы нагрузка была предсказуемой (в steady state повторов
≈ 10× новых). Для нас 20 = ~2 темы по 10 карточек — ровно темп учебника.

- лимит **в день**, не в сессию (как в Anki, сброс в 04:00); вторая сессия
  за день получит только повторы и остаток лимита
- в конце сессии кнопка **Learn 10 more** (аналог Custom study) — лимит
  защищает по умолчанию, но не блокирует
- настройка `newPerDay` в Settings, 5–100
- **видимый счётчик дня** на Home и в шапке сессии: `New today 7 / 20`;
  при достижении лимита — `20 / 20 · Learn 10 more`; сброс в 04:00 локального времени

### Сборка сессии для фильтра F (блок + темы + сложность)
1. `relearn` — незакрытые learning/lapsed из прерванных сессий (в F)
2. `due` — review с due ≤ сегодня (в F), сортировка по due asc, cap 200
3. `new` — state new (в F), по (№ темы, индекс карточки), взять
   `min(newPerDay − introducedToday, доступно)`
4. Порядок: relearn → due → new (повторы первыми). Позже опция «mix»
5. Неверно → вставка на `current + rand(10..15)`; < 10 в очереди → в конец;
   пусто → сразу. Закрытие — один верный ответ после ошибки
6. Состояние сохраняется после каждого ответа; на Home — «Continue session»
7. Итог сессии: new introduced, reviewed, lapses, first-try accuracy, score, time
8. На Home: подсказка «N cards due in other topics», чтобы фильтр не копил долг

## 6. Проверка ответа и ввод на телефоне

`answer.ts`: trim, схлопывание пробелов, `"` ↔ `'`, пробелы после запятых,
`None/True/False` без учёта регистра, `ValueError: msg` → `ValueError`,
`no error` / `none` / `nothing` для «не упадёт». `1.0` ≠ `1` (это смысл карточки).
`accepted[]` — альтернативы. Промах → показать оба + «I was right» (логируется
как override для доработки нормализатора).

Ввод на телефоне:
- `<input>` monospace, `autocapitalize=off autocorrect=off spellcheck=false enterkeyhint=go`
- chip-бар над клавиатурой: `None` `True` `False` `[ ]` `{ }` `( )` `' '` `,` `:` `Error` `no error` — вставка в позицию курсора
- кнопка **Just show me** — без ввода, затем Knew it / Didn't know (самооценка)
- после авто-вердикта карточка улетает вправо/влево по «Next» или свайпу;
  в режиме самооценки свайп вправо = Knew it, влево = Didn't know

## 7. Сообщения

`messages.ts`: пул ~120 фраз на английском с условиями `{bucket, event?, minStreak?}`,
weight, no-repeat последних 15. Бакеты: ≤ −5, −4…−1, 0, 1…4, 5…9, ≥ 10.
События: `first_card`, `cross_to_negative`, `cross_to_positive`, `hit_zero`,
`streak_3/5/10`, `wrong_streak_3`, `milestone_10/25/50`, `recovered`,
`session_done`, `all_cleared`.
Тон: программистский юмор, без сюсюканья. Ноль — `0 == False`, индексы с нуля,
`None is not 0`, off-by-one. Минус — «Anki calls this learning, not losing».
Плюс — похвала с нарастанием. Показ — строка под счётом, без модалок.

## 8. UI (mobile-first, English)

1. **Home** — счётчик `New today 7 / 20` и `Due today N`, 7 блоков с прогрессом
   (new / learning / due today / mature), мультивыбор тем и сложности,
   Start / Continue session, lifetime score.
2. **Session** — карточка: тема (ссылка на Notion), код с подсветкой
   (Shiki, 13px mono, горизонтальный скролл), вопрос, поле ввода + chip-бар,
   Show answer. После: ответ, объяснение (раскрывающееся), вердикт, override;
   fly-out анимация; счёт и фраза; прогресс очереди; в шапке — `New 7/20 · Due 3 · Relearn 2`.
3. **History** — вкладки Correct / Wrong; клик → карточка с открытым ответом;
   фильтр по блоку; в Wrong — счётчик lapses.
4. **Settings** — newPerDay, theme, reset progress, export / import JSON.

PWA: vite-plugin-pwa, manifest, offline, safe-area insets, `100dvh`.
Установленный на home screen PWA защищён от 7-дневной очистки storage в Safari;
плюс export/import как бэкап.

## 9. Контентный конвейер

1. `export_topics.py` → `topics.json` (120 тем).
2. На тему: 1 карточка на каждую «частую ошибку», 2–3 на ключевые сниппеты,
   1–2 на «самопроверку», где вопрос про вывод. Блок 1: 8–12 на тему (~350);
   блоки 2–7: 4–8 (~400).
3. `verify_cards.py` в CI: схема, лимиты строк, exec/pytest-сверка;
   расхождение → карточка не попадает в bank.
4. Порядок блоков: 1 → (самотест, UX) → 2 → 5 → 3 → 4 → 6 → 7.

## 11. Риски

- Неверные ответы в карточках → автопроверка exec/pytest; manual — ручное ревью.
- Неоднозначный вывод (repr float, порядок set) → не брать или `accepted[]`.
- Ввод скобок/кавычек на телефоне → chip-бар, мягкий нормализатор, «Just show me».
- Поздние блоки плохо ложатся в формат → типы `truth`/`value`/`pytest`, меньше карточек.
- Потеря прогресса в Safari → PWA на home screen + export/import.
- Шум сообщений → no-repeat, короткие фразы, без модалок.
